# 영상팀 워크플로우 구조도

성남시청 사진우 주무관의 AI 영상 제작 워크플로우를 **토목 도면 형식**으로 정리한 인터랙티브 구조도입니다. 발표 때 전체도(원경)에서 단계별로 줌인하며 설명하는 용도로 만들었습니다. 내용은 **2026-11-13** 시점의 실제 작업 파일 기준입니다. 기본은 발표 모드(짧은 경로)이고, 상세 시트는 부록으로 분리했습니다.

- 화면으로 보기: `index.html`을 브라우저로 열기 (GitHub Pages 링크는 레포 About 참고)
- 글로 읽기: [`docs/STRUCTURE.md`](docs/STRUCTURE.md) — 화면의 모든 시트를 순서대로 옮긴 텍스트 버전 (`python3 tools/export_structure.py`로 자동 생성)

## 전체 구조

```
발표 경로 (기본)
전체도 → 01 기획 → 02 음악 (실제 곡 20초) → △1 음악에 맞춰 기획 수정
       → 03 이미지 (실사 인물 시트를 다시 만든 실제 예 2장 · 참조의 뜻)
       → 04 영상화 ① 참조에 역할 주기 → ② 동작과 결과 (실제 참조 3장 · 프롬프트 네 줄 · 결과 프레임)
       → △2 참조를 고쳐서 해결 (날짜순으로 재구성한 사례 · 같은 구도의 전/후)
       → 05 후처리 → 05 사례 ① 화성 잉크 프레임(카드 05-1) → 사례 ② 빈 현수막에 글자(카드 05-4) → 06 편집 (사람 / AI 역할)

부록 (D 키) — 질문이 나오면 펼치는 자료
01 기획   : A 기획 순서와 확정 · B 스타일 바이블 · C 콘티 항목
02 음악   : A Suno 프롬프트 구조
03 이미지 : A 프롬프트 구조 · B 참조 규칙·검수 · C 모델 변경
04 영상화 : A 프롬프트 해부(실제 제출본) · B 검사→생성→검수 · C 반복 실수 검사 · D 모델·모드 변경
05 후처리 : A 후처리 구성 (+ 05-2 매돌이 · 05-3 푸드테크 사례 카드)
06 편집   : A 편집 규칙
00 공통   : A 위키 지도 · B 실패 → 경고 · C 근거와 한계
```

→ 만 누르면 발표 경로가 끝까지 이어지고 부록은 건너뜁니다. 주소 뒤에 `?full`을 붙이면 부록까지 이어서 넘깁니다.

## 시트로 바로 가는 링크

주소 뒤에 `#이름`을 붙이면 그 시트로 바로 갑니다. 예: `index.html#d04b`. 숫자 링크(`#7`)도 되지만 v0.5에서 04가 두 칸이 되어 6번 이후가 1씩 밀렸습니다. 이름 링크는 밀리지 않습니다.

| 시트 | 주소 뒤에 붙일 이름 |

| 04 ② 동작과 결과 | `#s4-2` |

## 용어

화면에는 한국어 이름을 먼저 쓰고 내부 식별자는 작게 적거나 뺐습니다. 아래는 원래 식별자와의 대응입니다.

| 용어 | 뜻 |
|---|---|
| 영상팀 / 레인 | Codex 세션을 단계(레인)마다 새로 띄워 일을 나누는 작업 체계. 레인 순서: director → music → planner → image_creator → image_qc → seedance → seedance_qc → package |
| 디렉터 | 사용자와 대화하며 승인·진행을 판단하는 메인 대화 (Claude Code 또는 Codex) |
| P0–P5 | 프리프로덕션 단계: 컨셉 · 스타일 바이블 · 콘티 · 이미지 · 선반 · 제작 |
| 잠금 / STALE | 단계 파일을 확정하는 것. 상류 파일이 바뀌면 하류 잠금이 무효(STALE)가 된다. 단, 생성 전 묶음(선반) 잠금은 2026-11-11부터 블록별 입력에 묶여, 입력이 그대로인 블록의 잠금은 유지된다(화풍 고정 문장이 바뀌면 전 블록, 인물 고정 설명이 바뀌면 그 인물이 등장하는 블록만 — preprod.py block_input_digest) |
| 생성 전 묶음 (선반, shelf) | 블록마다 제작 직전에 잠가 두는 프롬프트·참조·설정 묶음 |
| 블록 / 숏 | 블록 = Seedance 생성 1회(기본 15초), 숏 = 블록 안의 컷 |
| I2V / No-I2V | 시작 프레임 이미지를 영상으로 만드는 방식 / 시작 프레임 없이 참조만 붙여 생성하는 방식 |
| 화풍 고정 문장 / 인물 고정 설명 | style_block_en / identity_block_en — 모든 프롬프트에 원문 그대로 반복하는 문단 |
| 반복 실수 검사 (prompt_lint) | 사용자에게 거절된 문구 패턴 13개를 프롬프트에서 잡아내는 검사 |
| 지식 라우터 | 블록 속성으로 위키에서 필요한 섹션만 골라 넘기는 로컬 스크립트 |
| 교훈 장부 | 사용자 승인·거절에서 나온 규칙을 날짜와 함께 모은 위키 페이지 |
| 캡슐 | 대화가 압축·인계되기 전에 남기는 작업 요약 |

## 출처와 범위

- 각 시트 하단에 근거 파일을 적었습니다. 근거 파일은 작성자 로컬 환경(`~/.codex/skills`, `~/wiki`, Claude 메모리)에 있고 **이 레포에는 포함되지 않습니다**. 런타임 코드·규칙 일부는 공개 레포 [GnuDaSsa/video-team-workflow](https://github.com/GnuDaSsa/video-team-workflow)에 있습니다.
- 수치(메모리 62, 캡슐 147, 교훈 장부 34, 반복 실수 검사 규칙 13, 지식 카탈로그 33)는 2026-11-13에 실제 파일을 세었습니다. 하트 프롬프트 수집 경로는 11-13에 만들었고 아직 0건입니다. 화면에서는 이 수치 시트를 뺐습니다(지금의 00-C는 "근거와 한계" 시트입니다).
- 05 후처리: 성남 푸드테크와 「솔로몬의 선택」은 실제 원본 클립과 최종본의 비교입니다. 화성과 매돌이는 원본이 로컬에 없어 **최종본에서 효과 직전 프레임과 효과 순간**을 나란히 놓았고, 화면에도 그렇게 표기했습니다.
- 04 영상화의 참조 3장·프롬프트 인용·결과 프레임(assets/vid)은 성남시 MV 첫 15초 블록의 실제 제출 자료입니다(Seedance 2.5 · 5숏). assets/clips는 최종본·원본에서 자른 2.5–4초 클립입니다.
- 02 음악 화면의 레포 이름은 실제 이름(naqashmunir21/awesome-suno-prompts)으로 표기했습니다.
- △2 사례는 성남시 MV 라운지 장면의 실제 자료를 작업 메모와 날짜순으로 재구성한 것입니다. 참조 2장(assets/r2: REF_LOC_MEETUP_HALL_1 11-06, _2 11-08)과 클립 프레임 2장(assets/r3/same_before.jpg = 11-07 생성 클립 8초 지점, same_after.jpg = 11-08 생성 클립 8초 지점, 둘 다 레지스트리상 블록 B03)을 씁니다. 두 클립은 같은 구도이지만 같은 컷은 아니고(색감·잔·촛불 다름), 어느 생성에 어느 참조를 붙였는지는 기록이 없습니다. 그 사이 이미지 프롬프트도 고쳐 참조를 다시 만들었고, 같은 기간 영상 프롬프트를 바꿨는지는 확인하지 못했습니다. 그래서 참조만 바꾼 통제 비교가 아닙니다. "참조가 영상 프롬프트를 이긴다"는 교훈 장부(11-08)의 문장을 인용한 것입니다. 처음 참조는 거절 처리된 것이 아니라 대체된 것입니다. assets/r2의 b_leak·b_later 프레임은 v0.4부터 화면에 쓰지 않습니다.
- 03 이미지의 인물 시트 2장(assets/r3/img_earlier_face.jpg, img_seedream_face.jpg)은 성남시 푸드테크 영상의 보호자 캐릭터 시트에서 얼굴 패널만 잘라 낸 것입니다(이전 시트 → Seedream으로 다시 만든 승인본). 기존 시트에서 크롭만 했고 재생성·보정은 하지 않았습니다. 인용문은 2026-10-23 강의자료에 적어 둔 작성자 발언 원문입니다. 이전 시트를 만든 도구는 기록이 없어 적지 않았습니다.
- 04의 동작 문장(숏 1)과 04-A의 한 행(숏 3)은 성남시 MV 첫 15초 제출 프롬프트 원문입니다.
- 02 음악의 20초는 화성 공모전 최종본에 쓴 Suno 곡(HSCF_C05)의 20–40초 구간입니다. assets/r2/beatcuts.json은 분석이 결론에 이르지 못해 화면에 쓰지 않았습니다.
- 05-1의 "약 0.4초"는 assets/clips/hw_hit.mp4(30fps)에서 효과 구간을 프레임으로 센 값입니다(약 11프레임 ≈ 0.37초).
- 숏 수(1–8)·참조 12장은 모델 사양이 아니라 우리 런타임 검사 한도입니다. 지식 발췌 한도의 기본값은 실행기가 쓰는 배포 런타임이 6섹션·9,000자, 수정 중인 로컬 소스가 11섹션·14,000자입니다. 프로젝트 설정과 명령 인자가 이 값을 덮어쓸 수 있고, 특정 프로젝트에 실제로 쓰인 값은 확인하지 않았습니다.
- 04-B의 "이미 제출됐는지부터 확인"은 런타임 규칙 §2.5와 seedance25 production 문서, 04·06의 "생성한 15초가 곧 최종 15초는 아닙니다"는 seedance25 prompting 문서("Timestamps are pacing, not frame-exact cuts")가 근거입니다.
- 화면의 배지 네 가지(실제 자료 · 재구성 · 예시 · 원고의 비유)와 화면별 한계는 부록 00-C에 모았습니다.
